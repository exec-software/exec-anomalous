- [0093: Carry a semantic manifest in the program image](0093-carry-a-semantic-manifest-in-the-program-image.md) — Accepted. The interpreter route of ADR 0092 forces this: a generic image cannot describe the workload it carries.
- [0094: Map a program arena against a named profile](0094-map-a-program-arena-against-a-named-profile.md) — Proposed. The owned-mapping core admits one arena geometry by literal address, so a program-bearing task cannot be mapped at all: its arena minimum is 64 KiB against the native application's fixed 32 KiB. Geometry becomes a named profile the kernel validates before it maps anything, with the existing numbers held unchanged as one such profile.
- [0099: Boot a Ny vessel on the rite ABI](0099-boot-a-ny-vessel-on-the-rite-abi.md) — Proposed. The toolchain changes that removed ADR 0049's reverse-engineered shim, trap stubs and absent runtime make a real vessel possible: one Ny object entered through `__ny_entry`, linked against the shipped freestanding runtime, booted by this kernel, issuing its own `console_write` rites from inside Ny's control flow through a symbol the vessel defines and Ny declares with `@interop("host")`, reading the result back and writing again on the strength of it, then asking for a line through `session_input_read` and composing a third message around text it could not have contained. The region the kernel installs is the channel for the bytes, because a Ny object publishes nothing but its entry, and the fixture searches that region afterwards to tell what Ny composed from what it quoted. It also yields mid-`main`, and the fixture answers by leaving and resuming its address space, so the answer it composes afterwards from a pointer it held beforehand is what shows its state survived. The same image is then entered a second time to fail on purpose: the binding defines `__ny_host_fail`, so a Ny failure arrives as a rite and an exit status instead of a user task spinning where nothing can see it.
