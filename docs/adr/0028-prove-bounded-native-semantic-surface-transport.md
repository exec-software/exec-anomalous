# ADR 0028: Prove bounded native semantic-surface transport

- Status: Accepted
- Date: 2026-09-19

This record accepts one removable x86-64 proof in which a fixed ring-3 source
submits one explicitly versioned, redacted semantic-surface snapshot to one
exact ring-3 consumer through a kernel-owned copied slot. The proof binds the
transfer to trusted task and endpoint state plus the exact surface, scene,
revision, renderer generation, and delivery attempt without serializing ADR
0027's private Rust `render_snapshot` representation.

The accepted slice ends when the complete body has been copied to the exact
consumer and consumed from the transport slot. It does not complete an ADR
0027 render lease, attest presentation, publish semantic state, render pixels,
or enter the normal image.

## Context

ADR 0025 accepts one host-only canonical semantic scene whose committed human,
accessibility, and machine projections agree. ADR 0026 proves that one
build-generated, feature-private capsule can drive a supervised ring-3 renderer
and publish one complete replacement frame. ADR 0027 then accepts a separate
host-only transaction: one complete successor remains private through queued,
leased, ready, and presented phases, one fresh renderer may retry it, and its
paired semantics publish only after an exact trusted presentation receipt.

Those decisions deliberately leave a native transfer gap. ADR 0027's
`render_snapshot` is private local Rust data. It has no byte decoder, layout or
padding promise, magic, media type, negotiation rule, or stable ABI. Its
private service brand and move-only controls are authority precisely because
they cannot be reconstructed from public scalar fields. ADR 0026's 416-byte
capsule is also unsuitable as a live boundary: it is private to one fixed
standard-depth fixture, carries 25 commands and only the labels used by that
renderer, and omits live surface, base revision, renderer, and attempt
correlation.

A native boundary must therefore define new bytes deliberately. Copying the
memory of `render_snapshot`, casting scene enums, or promoting the ADR 0026
capsule would accidentally freeze implementation details while still failing
to convey authority. Conversely, putting a user pointer or shared page into a
message would leave the consumer exposed to mutation after validation.

The smallest next proof is only the copied transport. It should establish an
exact versioned encoding, split source and consumer rights, kernel-owned
one-slot backpressure, task-incarnation binding, copy-before-parse and
copy-before-consume behavior, and privacy-safe teardown. Renderer completion,
supervised retry, presentation evidence, semantic publication, and pixels are
separate compositions and must not be inferred from successful delivery.

## Decision

### Add a separate feature-only native proof

Add a top-level `semantic_surface_transport_test` feature with precedence over
the existing terminal feature proofs in combined-feature lint and link builds.
It owns a fixed source task, a fixed consumer task, their distinct grants and
mailboxes, one kernel endpoint, a closed transcript, and complete teardown.
All feature payloads, gates, helpers, markers, generated bytes, and test policy
remain absent from the ordinary image.

`semantic surface`, `source`, `consumer`, `snapshot`, and `endpoint` are
conventional descriptions of this experiment. This decision introduces no new
occult platform abstraction or nomenclature entry.

The proof remains x86-64 native. IA-32 execution and 32-bit Win32 ABI
translation remain future user-space compatibility-veil responsibilities and
cannot select or reinterpret this native boundary.

### Define two distinct rights and operations

Extend the provisional Rite namespace with two independent rights:

- `semantic_surface_submit`, assigned right bit `1 << 6`, permits the exact
  source task to offer one complete version-1 snapshot to its bound endpoint;
  and
- `semantic_surface_read`, assigned right bit `1 << 7`, permits the exact
  consumer task to poll and receive that endpoint's queued snapshot.

Assign operation values 7 and 8 respectively. Add one payload kind
for a version-1 semantic-surface snapshot and one for its fixed read request.
The successful read reply uses the snapshot payload kind. The exact numeric
values are accepted only for this pre-alpha proof and are not a stable external
ABI. A later change requires explicit compatibility review.

The existing `shell_minimum` and `display_manager_minimum` grants remain
unchanged. The source receives only `semantic_surface_submit | task_exit`; the
consumer receives only `semantic_surface_read | task_exit`. Neither task
receives console, physical input, semantic-session input, display update, or
the other side's surface-transport right.

Submit requires the snapshot payload kind, size 528, and an exact payload limit
of 528. Read requires the request payload kind, size 16, and an exact payload
limit of 16. The established admission precedence remains: malformed prefix,
unknown operation, invalid declared metadata, missing or excessive rights,
trusted-grant/task denial, operation/payload mismatch, then envelope bounds.
After an admitted body copy, malformed version-1 bytes return `bad_payload`, an
exact-correlation mismatch returns `denied`, and a full submit or empty read
returns payload-free `would_block`. Only a fully committed submit or delivery
returns `ok`.

The caller's `rights_present` value still only narrows a trusted kernel grant.
A numeric right, task, endpoint, scene, surface, revision, renderer, attempt,
trace, sequence, address, or payload value confers no authority.

### Add an exact fixed version-1 read request

Define `rite_semantic_surface_request_v1` as an exact 16-byte little-endian
body:

- offset 0: `u16 structure_size`, value 16;
- offset 2: `u16 version`, value 1;
- offset 4: zero `u32 flags`;
- offset 8: `u32 reply_capacity`, equal to the complete version-1 snapshot
  size; and
- offset 12: zero `u32 reserved`.

The read call requires the exact request size and payload limit. It carries no
caller-selected surface, endpoint, or receiver identity. The kernel recovers
the sole endpoint binding from the exact live consumer task and its channel.
An empty endpoint returns the existing payload-free `would_block` status. This
slice does not install a wait, retain a synchronous Rite admission across a
task switch, or add a scheduler wake primitive.

### Define one 528-byte semantic-surface snapshot body

Define `semantic_surface_snapshot_v1` as exactly 528 little-endian bytes. It is
the body carried by the accepted Rite snapshot payload kind, but its semantic
codec remains separate from the low-level Rite prefix types:

1. a 112-byte header;
2. eight one-byte label selectors followed by eight zero reserved bytes; and
3. twenty-five 16-byte command records.

The header fields and offsets are:

| Offset | Field | Version-1 rule |
| ---: | --- | --- |
| 0 | `u16 header_size` | 112 |
| 2 | `u16 version` | 1 |
| 4 | `u32 total_size` | 528 |
| 8 | `u32 flags` | zero |
| 12 | `u16 profile` | fixed desktop profile 1 |
| 14 | `u16 command_count` | exactly 21 or 25 |
| 16 | `u16 label_count` | 8 |
| 18 | `u16 command_size` | 16 |
| 20 | `u16 viewport_width` | 1,024 |
| 22 | `u16 viewport_height` | 768 |
| 24 | `u8 primary_enabled` | 0 or 1 |
| 25 | `u8 secondary_enabled` | 0 or 1 |
| 26 | `u8 focus` | explicit none, primary, or secondary code |
| 27 | `u8 disclosure` | explicit declared-public or protected code |
| 28 | `u8 depth` | explicit standard or flat code |
| 29 | `u8 motion` | explicit standard or reduced code |
| 30 | `u16 reserved` | zero |
| 32 | `u64 surface_slot` | nonzero correlation value |
| 40 | `u64 surface_generation` | nonzero correlation value |
| 48 | `u64 scene_slot` | nonzero correlation value |
| 56 | `u64 scene_generation` | nonzero correlation value |
| 64 | `u64 base_revision` | nonzero and immediately precedes revision |
| 72 | `u64 revision` | nonzero, nonwrapping successor |
| 80 | `u64 renderer_slot` | nonzero correlation value |
| 88 | `u64 renderer_generation` | nonzero correlation value |
| 96 | `u64 delivery_attempt` | version 1 accepts attempt one or two |
| 104 | `u64 reserved_2` | zero |

The eight selectors at offsets 112 through 119 correspond exactly to scene
slots zero through seven. Version 1 assigns explicit nonzero codes to
`Anomalous desktop`, `Anomalous`, `Navigation`, `Open shell`, `Inspect system`,
`Workspace`, `System workspace`, `System ready`, and `Protected status`.
Slots zero through six have their one fixed declared-public selector. Slot
seven has either `System ready` or `Protected status` according to disclosure.
Offsets 120 through 127 remain zero.

The exact selector codes are 1 through 9 in that listed order. The state codes
are `focus = none:0, primary:1, secondary:2`; `disclosure =
declared_public:0, protected:1`; `depth = standard:0, flat:1`; and `motion =
standard:0, reduced:1`. Boolean state fields accept only zero or one. These are
wire assignments, not casts of the corresponding Rust values.

Each command record begins at `128 + index * 16` and contains:

- one-byte explicit command-kind, shape, color, optional-secondary-color,
  slot, and active-state codes;
- a zero `u16` reservation; and
- `u16 x`, `y`, `width`, and `height` fields.

Version 1 assigns nonzero codes to every present command kind, shape, color,
and slot. Secondary color uses zero for none. Width and height are nonzero for
every present record, and checked endpoints remain inside 1024x768. Standard
depth requires exactly 25 present records. Flat depth requires exactly 21
present records and four entirely zero tail records. This gives every valid
body one canonical size and prevents uninitialized or padding bytes from
crossing the boundary.

The command-kind codes are `fill:1`, `outline:2`, `label:3`,
`enabled_marker:4`, `focus_outline:5`, `shadow:6`, and `highlight:7`. Shape
codes are `rectangle:1`, `text:2`, `enabled:3`, `disabled:4`,
`focus_absent:5`, and `focus_double_outline:6`. Color codes are, in order from
1 through 15, `canvas`, `surface`, `primary_fill`, `secondary_fill`,
`disabled`, `primary_text`, `secondary_text`, `on_accent`, `outline`,
`focus_outer`, `focus_inner`, `public_status`, `protected_status`, `shadow`,
and `highlight`. Slot codes are, in order from 1 through 8, `root`, `masthead`,
`navigation`, `primary_action`, `secondary_action`, `content`, `heading`, and
`status`. Active state accepts only zero or one; secondary color accepts zero
or one of the 15 color codes.

The wire code tables are independent of Rust enum discriminants. Unknown
codes remain ordinary integer data and reject before use. Explicit encode and
decode routines perform every endian conversion; neither architecture code nor
a client may copy a Rust structure as wire bytes.

The body intentionally omits the ADR 0027 private service brand, construction
and surface controls, renderer endpoint, render lease owner, prepared scene,
projection owners, local action and focus handles, presentation authority,
publication sequence, task identity, Rite trace and sequence, protected source
bytes and exact length, and arbitrary label text. Publication sequence is not
part of ADR 0027's snapshot/lease binding and is not invented here.

### Separate the core codec from the optional service adapter

Add a small `no_std`, allocation-free, unsafe-free
`anomalous-desktop-transport` codec outside the kernel. Its default core owns
the version-1 semantic body, explicit byte encoder/decoder, structural
validator, and typed decoded view without depending on the desktop scene or
service. The kernel and native consumer may use that core with default features
disabled; doing so must not pull host desktop policy into either target.

An optional `service_adapter` feature depends on
`anomalous-desktop-service` and its scene types. Its encoder takes an exact
borrowed `render_snapshot_view` plus its matching `render_lease`, checks their
public surface and revision agreement, and maps every field through exhaustive
named matches into the version-1 codec value. The service and scene crates do
not depend on the codec, so the dependency remains one-way.

Neither the core codec nor the optional adapter may inspect or expose
`render_snapshot`, derive its wire size from the private type, rely on padding,
use `transmute`, cast a scene enum, or copy object memory. A future internal
reordering, padding change, or alternate private snapshot representation
therefore need not change the native format. Only an intentional versioned
field mapping can do so.

For this proof, the build/conformance step constructs the actual ADR 0027 fixed
service fixture, submits one successor, acquires its exact render lease, borrows
the renderer candidate, and emits the source task's immutable version-1 body
through that adapter. Two otherwise identical fixtures with different valid
protected status sources and lengths must produce byte-identical bodies and
source payloads. This is conformance generation, not a deployed native scene
service and not evidence that ADR 0027's host state machine ran in ring 3.

The native consumer uses only the core codec and a target-side fixed-profile
validator. It does not enable `service_adapter`, depend on the service or scene
crates, or receive a private host owner. The kernel may depend on
`anomalous-abi` and the core codec with the adapter disabled, but not on the
scene, service, optional adapter, or renderer crates.

The encoded body and decoded view have no ambient `Debug`, `Display`, or
general serialization implementation. Named accessors are local disclosure
boundaries. The bytes remain copyable transport data, never a capability.

### Bind one kernel-owned copied endpoint

Create one move-only kernel endpoint with an unexposed, nonzero, nonwrapping
endpoint generation and one exact binding containing:

- the complete source task incarnation;
- the complete consumer task incarnation;
- the expected surface and scene slot/generation pairs;
- the expected base and successor revisions;
- the expected renderer slot/generation and delivery attempt; and
- the endpoint's own private generation.

The endpoint state is exactly `empty`, `queued`, or `closed`. Its queued state
owns one complete 528-byte body. Public fields duplicated in the body are
checked against trusted endpoint state, but equality remains correlation, not
authority. Equal public values in a different endpoint generation, task
incarnation, or kernel owner cannot submit or receive.

After ordinary Rite admission, submit handling copies the complete user body
once into zeroed kernel scratch and stops consulting user memory. It validates
the fixed ABI shape and exact endpoint correlation before preparing any state
change. Commit copies the complete canonical body into the empty endpoint and
only then produces an `ok` reply. A queued endpoint returns `would_block`
without overwriting, dropping, comparing, coalescing, or reordering either
body. Malformed, stale, foreign, denied, oversized, and failed-copy submissions
leave the endpoint unchanged.

Structural wire validation in the kernel is limited to fixed format safety:
sizes, versions, flags, reservations, known tags, canonical tails, checked
bounds, and the exact trusted correlation tuple. It does not derive scene
policy, actions, focus authority, presentation state, or machine semantics.
The unprivileged consumer independently validates the complete fixed profile
before exposing a typed view.

The successful submit makes the endpoint, not the source mailbox or source
task, owner of the copied body. The source may then exit and have its channel,
mailbox, mappings, task storage, and address space withdrawn without invalidating
the queued body.

### Copy to the exact consumer before consuming the slot

An admitted read first copies and validates the complete 16-byte request into
kernel-owned state. If the endpoint is queued, the transport encodes a complete
reply prefix and obtains the exact saved body without changing endpoint state.
It then:

1. invalidates the destination reply header;
2. clears the complete 528-byte reply-body area;
3. copies the complete queued body;
4. writes every remaining reply-prefix field;
5. commits consumption and clearing of the exact queued endpoint owner; and
6. publishes the reply header size last.

Every fallible span, mapping, binding, body, and destination check occurs before
step 1. A host copy model injects failure at every destination-body offset
before commit and requires the endpoint body and all authority state to remain
unchanged while the destination header remains invalid. Under the native
proof's fixed mapped-page and serialized BSP contract, steps 1 through 6 are
bounded and non-rejecting; a hardware mapping fault is fail-stop.

Reading the body consumes only the transport slot. It does not call ADR 0027
`complete_render`, change `leased` to `ready`, release the service's pending
candidate, mint a prepared presentation, attest pixels, or publish semantics.
A later composition must define the acknowledgement and presentation evidence
that connect those state machines.

### Prove one source-to-consumer lifecycle

The fixed source and consumer have separate RX image, RW+NX Rite mailbox, and
RW+NX stack extents with absent guard pages, no framebuffer mapping, and no
shared user-writable page. The source image contains the generated snapshot;
the consumer image must not contain or map a second copy of it.

The accepted native lifecycle is:

1. the source enters and proves a read-right denial;
2. malformed and wrong-freshness submissions reject without occupying the
   endpoint;
3. one exact valid submission queues all 528 bytes;
4. one duplicate submission reports full backpressure without mutation;
5. the source exits terminally and its task-owned resources are withdrawn while
   the endpoint retains the copied body;
6. the consumer enters and proves a submit-right denial;
7. a malformed read request rejects without consuming the body;
8. one exact read receives and validates every defined field and byte;
9. a duplicate read returns payload-free `would_block`;
10. the consumer exits terminally; and
11. endpoint, transport, task, channel, scheduler, mapping, address-space, and
    allocator ownership are cleared and restored exactly.

The proof may use the existing scheduler and terminal-exit mechanisms to select
the consumer after source exit. It does not add a general producer/consumer
scheduler policy or supervision relationship.

### Keep content and evidence private by default

The native body contains only fixed public selectors, redaction, drawing
tokens, geometry, state, and correlation metadata. That does not make it
ambient telemetry. The source payload, endpoint storage, scratch pages,
mailboxes, consumer view, and task images are cleared and verified before
physical reuse. This is logical lifetime evidence, not secure erasure.

Feature success records may contain only fixed lifecycle kinds, bounded byte
and call counts, resource counts, and boolean invariant results. They omit
snapshot or mailbox bytes, labels, label selectors, scene state, rectangles,
surface/scene/renderer/task/endpoint identities, revisions, attempts, Rite
sequences and traces, addresses, pointers, protected metadata, and timestamps.
The verifier rejects malformed framing, unknown or reordered records, any
error/fatal record, and every forbidden field or fixture sentinel.

Protected source values and exact lengths must not affect the native body,
source image, consumer result shape, error shape, or transcript. Operation
activity, fixed proof ordering, and externally measured timing remain visible.
This decision adds no padding beyond the canonical fixed body, batching,
traffic shaping, activity noninterference, telemetry sink, persistence, audit
provenance, or retention policy.

## Required invariants

- Source and consumer rights remain distinct, and neither task can invoke the
  opposite operation or obtain authority from caller-declared bits.
- The exact task incarnations and private endpoint generation authorize the
  transfer; every wire identity and freshness value is correlation only.
- The private ADR 0027 service brand and move-only authority owners never enter
  the wire, kernel endpoint, consumer image, or transcript.
- Version-1 bytes are produced and consumed through explicit little-endian
  field mappings, never through the memory representation of a Rust value.
- Exactly one complete body may occupy the endpoint. Full capacity never
  overwrites, drops, coalesces, reorders, or compares a second body.
- Submit copies the complete body before parsing and commits the endpoint only
  after all fallible validation succeeds. Source retirement cannot invalidate
  the resulting kernel-owned copy.
- Read copies the complete body before consuming the endpoint and publishes a
  valid reply header only after body copy and source consumption complete.
- Rejection and injected copy failure leave the complete endpoint and authority
  state unchanged; stale bytes cannot survive a shorter or empty reply.
- The consumer validates all 528 bytes and the complete fixed profile before
  use, while the kernel gains no scene, focus, action, or presentation policy.
- Protected source values and exact lengths affect no body, target image,
  result shape, or transcript, while activity and timing remain explicit
  nonclaims.
- Successful delivery changes only transport ownership. It proves no renderer
  readiness, correct pixels, presentation, scanout, or semantic publication.
- Successful teardown clears all feature-owned mutable storage, restores every
  tracked resource, and leaves the normal image free of feature code and data.

## Non-goals

This decision does not define or implement:

- native execution of the ADR 0027 desktop service or a production scene host;
- render-lease completion, a prepared presentation, presentation control or
  receipt, semantic publication, publication sequence transport, or producer-
  slot release;
- renderer restart, supervision, acknowledgement, retry, cancellation, or
  recovery after a consumer has received a body;
- a renderer, rasterizer, pixel oracle, display update, framebuffer stage,
  presenter, scanout proof, page flip, vsync, GPU command, DMA, or fence;
- a compositor, window server, window/surface lifecycle, z-order, occlusion,
  damage, application surface, multiple displays, or normal-image desktop;
- input or focus routing, hit testing, action execution, secure attention,
  consent, authentication, authorization policy, clipboard, drag and drop, or
  application launch;
- transport of the accessibility or machine projection, action descriptors,
  canonical scene owner, protected source owner, or local control handles;
- arbitrary scenes, topology, geometry, labels, text, command counts, fonts,
  shaping, localization, scaling, animation, themes, or dynamic profiles;
- more than one source, consumer, endpoint, surface, queued body, or successful
  delivery;
- blocking reads, wait/wake, broadcast, fan-out, general IPC, arbitrary user
  pointers, shared memory, zero copy, fairness, priorities, deadlines, quotas,
  producer admission, or denial-of-service containment;
- concurrency, threads, SMP ordering, NMI enablement, hostile simultaneous
  mailbox mutation, DMA/IOMMU isolation, or a general user-copy recovery path;
- a stable scene, surface, renderer, graphics, Rite, task, or compatibility

- ambient logging, screenshots, Oracle or Eidolon capture, history,

  noninterference, or side-channel resistance; or
- an IA-32 kernel or native foreign-platform ABI.

## Acceptance requirements

ABI, core-codec, and optional-adapter tests must cover:

- exact numeric right, operation, payload, profile, tag, and selector values;
- exact request and snapshot sizes, every field offset, explicit little-endian
  encoding, flags, reservations, fixed reply capacity, and compile-time bounds;
- zero, unknown, maximum, wrapped, inconsistent, truncated, trailing, and
  wrong-version values for every header and record field class;
- all valid command/shape/color/secondary/slot/state tags, checked rectangles,
  21- and 25-command forms, canonical zero tail, all eight label positions, and
  both status selectors;
- all 64 valid scene states and rejection of all 32 states that focus a
  disabled action;
- preferably all 4,096 accepted ADR 0027 state transitions, acquiring the real
  leased view and requiring complete decoded typed-field equality without any
  private-layout or padding comparison;
- wrong lease/view surface and revision pairings, explicit exhaustive enum
  mapping, and compile-time or source inspection forbidding raw private-object
  copying, transmutation, and discriminant casts;
- two valid protected sources with different bytes and lengths producing
  byte-identical 528-byte bodies and byte-identical native source payloads,
  with neither source present in generated files, images, diagnostics, or logs;
  and
- dependency inspection proving that the Rite ABI and core codec remain free of
  scene/service policy and that the kernel and consumer do not enable the
  service adapter or link the scene, service, protected fixture, or ADR 0026
  capsule implementation.

Endpoint, Rite, and transport host tests must cover:

- source and consumer right subsets, wrong task and circle incarnations,
  caller-right overclaim, operation/payload mismatches, and documented error
  precedence before endpoint inspection;
- exact endpoint/source/consumer/surface/scene/base/revision/renderer/attempt
  binding, equal public values under a foreign endpoint generation, stale
  values independently, nonzero construction, nonwrapping advancement, and
  exhaustion without mutation;
- empty read, one successful submit, full-slot backpressure, duplicate submit,
  one successful delivery, duplicate read, close, and teardown;
- source-mailbox mutation after submission and complete source-task retirement,
  proving the endpoint owns an independent immutable copy;
- every malformed body and read request, wrong reply capacity, page boundary,
  stale mapping, foreign mapping, additional writable alias, and incomplete
  destination span;
- injected failure at every one of the 528 source-copy offsets and every one of
  the 528 destination-copy offsets, proving exact endpoint/channel/task state,
  an invalid destination header, and no premature source consumption;
- long nonzero reply data followed by empty `would_block` and teardown,
  proving complete scratch, mailbox-body, endpoint, and task-storage clearing;
  and
- bounded transition traces for prepare, commit, rejection, owner drop,
  terminal task exit, endpoint close, replay, and restoration.

The x86-64 QEMU proof must show:

- two fixed tasks with disjoint grants and inspected RX, RW+NX mailbox, and
  RW+NX stack extents, absent guards, no shared writable page, and no user
  framebuffer mapping;
- the exact ordered denial, malformed, freshness, submit, backpressure, source
  exit, consumer read, empty-read, and consumer-exit lifecycle;
- source retirement before delivery while the independent endpoint copy remains
  intact;
- complete 528-byte consumer equality against an independent typed oracle,
  header-last publication, and consumption exactly once;
- complete channel, task, scheduler, endpoint, mapping, address-space, scratch,
  and allocator teardown with exact accounting restoration; and
- a strict closed-world transcript containing no forbidden content or
  correlating field.

Acceptance also requires formatting, script checks, warning-denied host and
x86-64 Clippy, the complete configured host suite, explicit all-feature
freestanding compilation and strict final linking with the new feature's
precedence, artifact inspection, the established non-VirtualBox QEMU regression
matrix plus a dedicated semantic-surface-transport smoke target, and a final
`normal-exclusion` run. VirtualBox is not required because this proof
does not change Threshold or the ordinary-image boot path.

## Acceptance evidence

Accepted from implementation commit `228a168` (`Implement bounded native
semantic surface transport`). The implemented transport fixes the ABI described
above: the submit and read rights are `1 << 6` (`0x40`) and `1 << 7` (`0x80`),
their operations are 7 and 8, the fixed read request is 16 bytes, and the
version-1 snapshot body is 528 bytes.

The inspected native inputs were deliberately bounded and content-free in the
acceptance record. The flat source image was 2,384 bytes (one page) and the
flat consumer image was 5,094 bytes (two pages). Their generated ELF artifacts
were distinct from those flat images:

- source ELF: 1,107,792 bytes,
  `8efcac631ad19bff57938b5f1aac82d4b3d9df0c2a6009bff05e8f936d6c0046`;
- generated snapshot: 528 bytes,
  `97a7e5a8544f2a8a3584beb6df6d1f6052627184df7469c8674545c7fa41871b`; and
- consumer ELF: 1,185,928 bytes,
  `79076d34284168f8c7b3452e8d7610f6a53cba44b60fa89dc7d001a9cc654f94`.

The dedicated QEMU transport transcript completed with 11 Rite calls, 9 body
copies, 2,176 copied body bytes, 1 committed submission, 1 delivery, 1
backpressure result, 2 Rite authority denials, 2 malformed-body/request
results, 2 task exits, and 2 restored kernel continuations. The two denials
are the disjoint channel-right checks; the admitted endpoint freshness proof
remains separately exact (`wrong_surface`) and does not inflate that authority
metric.

Host and native evidence covered every source and destination copy-fault offset
through the 528-byte body, with no premature consumption, publication, or
state mutation. It also established protected-source privacy noninterference:
different protected source bytes and lengths produced the same allowed body
and native source payload, while forbidden private inputs were absent from the
inspected artifacts and transcript. The successful lifecycle proved
header-last reply publication, stale-reply clearing, source retirement before
delivery from the independent copied endpoint slot, one-time consumption, and
exact teardown/accounting restoration.

Acceptance verification included the full `make check`, the configured QEMU
regression matrix and dedicated semantic-surface transport smoke target,
warning-denied host and x86-64 Clippy, all-features precedence/link and
artifact checks, and normal-image exclusion. No VirtualBox run was needed:
this feature is transport-only and leaves the ordinary Threshold boot path
unchanged.

This acceptance is not evidence of rendering, presentation, scanout, or
semantic publication. It accepts only the bounded copied transport boundary;
those later compositions remain outside this ADR.

## Consequences

With acceptance, Anomalous has an explicit native byte boundary for the fixed
renderer-facing surface projection without making the host service's private
representation or authority owners into an ABI. One source can retire after
copy, one consumer can receive the exact body once, and neither public IDs nor
shared memory become authority.

The proof intentionally leaves the important next composition visible. Native
delivery is not renderer readiness. Emptying the transport slot is not release
of ADR 0027's pending producer slot. A later decision must bind consumer
acknowledgement, supervised replacement, actual presentation evidence, and the
host semantic transaction before any native path may mint a presentation
receipt or publish revision N+1.

The fixed 528-byte body and one-slot polling endpoint favor auditability over
generality or throughput. Multiple surfaces, queues, blocking, cancellation,
damage, and stable format negotiation need separate policy and evidence.

## Alternatives considered

### Serialize `render_snapshot` directly

Rejected. Rust field order, enum representation, `Option` niches, padding, and
private implementation changes are not a wire contract. It would also confuse
copyable data with the service's private authority brand.

### Promote ADR 0026's render capsule

Rejected. That capsule is intentionally feature-private, covers one exact
25-command fixture, omits the complete ADR 0027 label and freshness view, and
has no live authority binding. Reusing it would silently broaden an accepted
nonclaim.

### Map or share the service snapshot with the consumer

Rejected. A shared user-writable mapping reopens time-of-check/time-of-use
mutation and lifetime questions and exposes implementation layout. One bounded
copy gives the endpoint a clear owner and teardown rule.

### Use one bidirectional surface operation and one right

Rejected. Source publication and consumer receipt are different authority
domains. Separate rights and operations make accidental role reversal and grant
overreach directly testable.

### Add submit, acquire, and completion operations together

Deferred. An explicit completion would begin the ADR 0027 `leased -> ready`
composition and would need retained acknowledgement authority, renderer-fault
behavior, retry, and service-owner return. The accepted two-operation proof
establishes the copied transport first without claiming that broader state
transition.

### Bind presentation evidence in the same ADR

Deferred. Presentation requires the renderer, complete-frame staging, presenter
ownership, receipt provenance, and semantic publication ordering. Combining it
with the first live wire would make failures difficult to localize and would
invite delivery to be mistaken for presentation.

### Add blocking and exact wake now

Deferred. ADR 0022 already proves the relevant fixed pending-read and exact-wake
mechanics for a different private endpoint. Polling keeps this proof focused on
surface encoding, source-to-kernel copy, endpoint ownership, and kernel-to-
consumer copy. A later general IPC design may reuse the established wait
invariants without duplicating them here.

## Reversal plan

Remove the feature, the two provisional operations and rights, version-1
codec and optional adapter, endpoint, fixtures, verifier, and normal-image
exclusions.
ADRs 0024 through 0027 remain valid: presentation, canonical scene,
supervised-renderer composition, and host transaction ownership do not depend
on this transport proof.
